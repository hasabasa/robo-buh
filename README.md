# robo-buh — робот-бухгалтер для упрощёнки РК

Автоматическая бухгалтерия для МСБ Казахстана на СНР «упрощённая декларация»:
собирает доход из всех каналов, считает налоги, готовит формы **910.00** (за себя)
и **200.00** (по работникам), даёт клиенту подписать их **его собственной ЭЦП**
(NCALayer, ключ не покидает машину клиента) и ведёт к сдаче в КГД.

## Охват MVP

- **ИП и ТОО на упрощёнке** (форма 910.00 полугодовая + форма 200.00 ежеквартальная)
- Источники дохода: Kaspi Shop API · банковские выписки (MT940, 1CClientBankExchange,
  CSV/XLSX, PDF→VLM) · ОФД (Webkassa) · ручной ввод
- Соцплатежи ИП за себя (ОПВ/ОПВР/СО/ВОСМС), календари обязательств, пеня
- Модуль задолженности: долги/аресты по ИИН/БИН + динамика пени
- Светофор лимита СНР (600 000 МРП/год)

Вне MVP: ЭСФ, ОУР, интеграция 1С, собственный M2M-канал ИСНА (Фаза 5, после
одобрения заявок Smart Bridge).

## Архитектура

```
backend/        FastAPI + asyncpg (Python 3.12)
streamlit_app/  Streamlit — фронт прототипа (Фазы 1–3); продакшн-UI на Next.js позже
docker/         compose: backend · streamlit · postgres · redis · ncanode
specs/          XSD/ФЛК форм, справочники (КНП, ставки маслихатов)
```

Подписание ЭЦП в Streamlit — через встраиваемый JS-компонент (WebSocket к локальному
NCALayer на `wss://127.0.0.1:13579`, метод `basicsSignXML`), логика та же, что в
`ncalayer-js-client`.

Ключевые принципы:
- **ЭЦП никогда не передаётся** — подписывает клиент локально через NCALayer
  (`basicsSignXML`), сервер только верифицирует через NCANode.
- **Налог с оборота** — учитываем только доходную сторону; расходы/первичка не нужны.
- Отсутствие данных ≠ ноль дохода: спорные операции идут в очередь ручной сверки.
- Все налоговые константы — в конфиг-справочнике `backend/app/taxconfig/`,
  ничего не зашито в логике.

## Запуск (dev)

```bash
cp .env.example .env       # заполнить секреты
docker compose -f docker/docker-compose.yml up -d --build
# backend: http://localhost:8000/docs · frontend: http://localhost:3000
```

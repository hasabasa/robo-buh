# Продукт B — полная бухгалтерия ОУР (модель «слой сверху»)

Второй продукт robo-buh параллельно A (упрощёнка). Для ТОО/ИП на **общеустановленном
режиме (ОУР)**: формы **100.00 (КПН), 300.00 (НДС), 200.00 (зарплата)**. Целевой сегмент —
опт/HoReCa/торговля с НДС и работниками.

## Стратегия: НЕ конкурировать с 1С, а встать слоем сверху

robo-buh = **налоговый/комплаенс-слой поверх системы, в которой бизнес уже работает**.
Мы не переписываем операционный учёт (продажи, склад, нал/безнал) — берём данные из того,
что у клиента уже есть, и делаем то, чего эти системы НЕ делают: считаем КПН/НДС/210,
формируем ФНО, сдаём в КГД, сводим контуры. Это снижает ответственность (цифры из системы
клиента, а не выдуманные) и ускоряет выход на рынок (коннектор < полного бух-движка).

```
Коннекторы (данные) → income_ledger (норм.) → НАЛОГОВОЕ ЯДРО (наше) → сдача/сверка
```

## Приоритет коннекторов

| Приоритет | Источник | Статус API | Роль |
|---|---|---|---|
| **Костяк (всегда)** | **ЭСФ** (esf.gov.kz, SOAP) | SDK есть | продажи/покупки/НДС/контрагенты — универсально для НДС-плательщиков |
| **Костяк (всегда)** | **банк-выписка** (MT940/1C/PDF) | ✅ построено | движение денег |
| **Костяк (всегда)** | **ОФД** (Webkassa/ReKassa) | открытый API | наличная выручка |
| **Обогатитель 1** | **iiko** (iikoServer/Cloud API) | 🟢 открытое | HoReCa: продажи, нал/безнал, склад, себестоимость |
| **Обогатитель 2** | **1С** (OData 8.3.5+) | 🟢 если облачная/веб-сервер; 🟡 локальная → файлобмен | учёт, проводки, закупки |
| По запросу | **R-Keeper** (XML-интерфейс) | 🟡 платная лицензия на объект | рестораны |
| Фолбэк | **Умаг** | 🔴 нет открытого API | клиентов закрываем через выписки+ОФД (Умаг дружит с WebKassa/ReKassa) |

**Правило:** ЭСФ+банк+ОФД строим всегда (универсально); iiko и 1С-OData — топ-2 коннектора
для тех, у кого есть; R-Keeper/Умаг — не блокеры, их клиентов ведём фолбэком по выпискам.

## Подтверждённые правила ОУР-2026 (сверено 26.08.2026, НК 214-VIII)

**КПН (форма 100.00, годовая):** ставка **20%** налогооблагаемого дохода. Авансовые платежи —
расчёт до декларации ОТМЕНЁН; за 1 кв. считает УГД (1/12 прошлого периода), уплата до 25 числа.
⚠️ Расходы на покупку у лиц **на упрощёнке в вычеты НЕ включаются**.

**НДС (форма 300.00, квартальная):** ставка **16%** (льготная 5%→10%). Порог постановки
**10 000 МРП** (43,25 млн ₸). К уплате = исходящий − входящий (к зачёту по полученным ЭСФ).
Срок до 15 числа 2-го мес. после квартала.

**Зарплата (форма 200.00, квартальная):**
- ИПН у источника **10%** (15% свыше ~36,7 млн ₸/год); база = оклад − ОПВ − ВОСМС − вычет **30 МРП** (лимит 360 МРП/год)
- удержания с работника: ОПВ **10%** (до 50 МЗП), ВОСМС **2%** (до 20 МЗП)
- платежи работодателя: ОПВР **3,5%**, СО **5%** (1–7 МЗП), ООСМС **3%** (до 40 МЗП), соцналог **6%** (ТОО)
- ⚠️ 2026: взаимозачёт соцналога и соцотчислений ОТМЕНЁН.

Все ставки — в `backend/app/taxconfig/kz_2026.py`.

## Переиспользование из A
income_ledger (расширен колонками vat_amount/vat_rate/expense_category/is_deductible/esf_id),
приём выписок, движок пени, контур ЭЦП (NCANode), генератор XML+ФЛК, гейт КГД (валидация),
RAG. Налоговые движки 910 — образец структуры для 100/300/200.

## Фазы B
1. **НДС-движок (300.00)** — ядро для опт-сценария: исходящий/входящий из ЭСФ+ledger, зачёт, форма.
2. **ЭСФ-коннектор** — чтение выставленных/полученных ЭСФ (SOAP, доступ по сертификату клиента).
3. **Зарплатный движок (200.00)** — ставки confirmed выше.
4. **КПН-движок (100.00)** — годовая агрегация, вычеты, авансовые.
5. **iiko-коннектор** + сверка контуров (goszakup→ЭСФ→банк→ФНО).

## Риски
- Ответственность за расчёт → модель «робот считает, клиент/бухгалтер проверяет и подписывает ЭЦП».
- Доступ к ЭСФ клиента → по его сертификату/доверенности (юр-нюанс уточнить).
- Точная структура форм 100/300/200 → по официальным машинным шаблонам СОНО (как 910).
- Вычитаемость расходов по КПН (покупка у упрощенцев не вычитается) → учесть в классификаторе.
